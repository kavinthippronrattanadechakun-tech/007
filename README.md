# PremiumHub — เว็บร้านค้า Next.js + Supabase + Vercel

## สถานะระบบ (อ่านก่อนเปิดรับเงินจริง)
- สมัคร/ล็อกอิน Supabase Auth, ดูสินค้า, ดูยอดกระเป๋า, ส่งสลิป, ดูประวัติ, ซื้อด้วยยอดเงิน, หน้าตรวจสลิปแอดมิน
- **ตรวจสลิปแบบรอแอดมินยืนยัน ไม่ใช่ระบบตรวจสลิปอัตโนมัติ** ตรวจ SHA-256 กันรูปเดิมซ้ำได้ แต่รูปที่ครอป/แก้ไขอาจหลบการตรวจนี้ได้ ต้องเช็คเลขอ้างอิงและยอดกับธุรกรรมธนาคารจริงทุกครั้ง
- แอดมินต้องกรอกเลขอ้างอิงธนาคาร; ฐานข้อมูลบังคับ unique reference และทำธุรกรรมเพิ่มยอดแบบ atomic เพื่อป้องกันอนุมัติซ้ำ
- สินค้าทั้งหมดตั้ง `active=false` เพื่อไม่เปิดขายสิทธิ์ที่ยังไม่ยืนยันการจำหน่าย; แอดมินสามารถเปิดเฉพาะรายการที่ได้รับอนุญาตใน Supabase Table Editor
- สินค้าแบบ `delivery_type='code'` ส่งโค้ดจาก `stock` อัตโนมัติแบบ atomic และป้องกันโค้ดซ้ำ; แบบ `manual` สร้างคำสั่งซื้อสถานะรอดำเนินการ **ยังไม่มีหน้าส่งสินค้าโดยแอดมิน**
- ไม่ใช่ระบบตรวจสลิปปลอมอัตโนมัติ ไม่ใช่ระบบเชื่อมธนาคาร ไม่ใช่ระบบคืนเงิน/เคลมอัตโนมัติ; ต้องทำเพิ่มเติมก่อนใช้งานเชิงพาณิชย์

## ติดตั้งบน Vercel ผ่าน GitHub
1. อัปโหลดไฟล์ทั้งหมด **ภายในโฟลเดอร์นี้** ไป repository (ต้องมี `app/`, `lib/`, `supabase/`, `package.json` อยู่ชั้นบนสุด)
2. สร้าง Supabase project: https://supabase.com/dashboard
3. เปิด SQL Editor วางเนื้อหา `supabase/schema_secure.sql` แล้ว Run (ทำเพียงครั้งเดียวบนโปรเจกต์ใหม่)
4. ใน Supabase Authentication ตั้งค่า Email sign-in และ Site URL ให้ตรงเว็บ Vercel
5. ใน Vercel > Project > Settings > Environment Variables เพิ่มค่าจาก `.env.example` (อย่าอัปโหลด `.env` ที่มี secret ขึ้น GitHub)
6. `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` จาก Supabase API settings (URL ต้องเป็น https://PROJECT.supabase.co โดยไม่มี /rest/v1/; ใช้ Publishable key หรือ legacy anon key เท่านั้น); `SUPABASE_SERVICE_ROLE_KEY` เป็น **secret server-only** ห้ามตั้งชื่อขึ้นต้น NEXT_PUBLIC
7. ตั้ง `BANK_NAME`, `BANK_ACCOUNT_NAME`, `BANK_ACCOUNT_NUMBER` เป็นข้อมูลบัญชีรับโอนที่ถูกต้อง
8. Deploy ใหม่ แล้วสมัครสมาชิกเพื่อทดสอบ
9. กำหนดแอดมินด้วย SQL Editor **เฉพาะ user id ที่ตรวจสอบแล้ว**: `update public.profiles set is_admin=true where id='UUID-ของเจ้าของร้าน';` อย่าให้ผู้ใช้ตั้งสิทธิ์แอดมินเอง
10. เพิ่มสต็อกเฉพาะคีย์/สิทธิ์ที่ได้รับอนุญาตใน Supabase Table Editor ตาราง `stock`; เปิด `products.active=true` เฉพาะสินค้าที่ถูกต้องและพร้อมขาย; ถ้าเป็น code ให้เปลี่ยน `delivery_type='code'`

## ทดสอบก่อนเปิดขาย
- ผู้ใช้ทั่วไปอ่าน/เปลี่ยนยอดคนอื่นไม่ได้; ห้ามเข้าหน้าแอดมินโดยไม่มีสิทธิ์
- สลิปเดิมซ้ำ, เลขอ้างอิงเดิมซ้ำ, กดอนุมัติซ้ำ ต้องไม่เพิ่มยอดอีก
- กดซื้อพร้อมกันหลายหน้าต้องไม่ติดลบ/ไม่ส่งคีย์ซ้ำ
- ไม่มีคีย์ในสต็อกต้องไม่หักเงิน; สินค้าปิดขายต้องกดซื้อไม่ได้
- ใช้ธุรกรรมทดสอบจริงกับบัญชีธนาคารและตรวจยอดด้วยมือก่อนเปิดใช้

## ข้อจำกัดและความปลอดภัย
- ระบบตรวจแค่ **hash ของไฟล์ภาพ** และเลขอ้างอิงที่แอดมินกรอก ไม่สามารถยืนยันว่ารูปสลิปแท้โดยอัตโนมัติ ต้องใช้ผู้ให้บริการตรวจสอบธุรกรรม/ธนาคารที่เชื่อถือได้เพื่อทำ auto-verify จริง
- ไม่เก็บรหัสผ่านลูกค้าหรือบัญชีของผู้ให้บริการภายนอกเป็นสต็อก; ให้ใช้เฉพาะโค้ดหรือสิทธิ์ที่ได้รับอนุญาต
- การจำหน่าย Netflix, ChatGPT, Gemini ต้องเป็นไปตามสิทธิ์การขายและเงื่อนไขของผู้ให้บริการ; อย่าเปิดขายบัญชีแชร์หรือบัญชีที่ไม่ได้รับอนุญาต
- ก่อนเปิดรับเงินจริงควรเพิ่ม rate limiting, CAPTCHA, audit logs, ช่องทางติดต่อ, นโยบายคืนเงิน/ความเป็นส่วนตัว, สำรองฐานข้อมูล, กระบวนการกระทบยอดธนาคาร และทดสอบการใช้งานจริง

## รันในเครื่อง
`npm install` แล้ว `npm run dev` (สร้าง `.env.local` จาก `.env.example`)
