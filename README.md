# PremiumHub — เว็บร้านค้า Next.js + Supabase + Vercel

## สถานะระบบ (อ่านก่อนเปิดรับเงินจริง)
- สมัคร/ล็อกอิน Supabase Auth, ดูสินค้า, ดูยอดกระเป๋า, ส่งสลิป, ดูประวัติ, ซื้อด้วยยอดเงิน, หน้าตรวจสลิปแอดมิน
- **ตรวจสลิปแบบรอแอดมินยืนยัน ไม่ใช่ระบบตรวจสลิปอัตโนมัติ** ตรวจ SHA-256 กันรูปเดิมซ้ำได้ แต่รูปที่ครอป/แก้ไขอาจหลบการตรวจนี้ได้ ต้องเช็คเลขอ้างอิงและยอดกับธุรกรรมธนาคารจริงทุกครั้ง
- แอดมินต้องกรอกเลขอ้างอิงธนาคาร; ฐานข้อมูลบังคับ unique reference และทำธุรกรรมเพิ่มยอดแบบ atomic เพื่อป้องกันอนุมัติซ้ำ
- สินค้าทั้งหมดตั้ง `active=false` เพื่อไม่เปิดขายสิทธิ์ที่ยังไม่ยืนยันการจำหน่าย; แอดมินสามารถเปิดเฉพาะรายการที่ได้รับอนุญาตใน Supabase Table Editor
- สินค้าแบบ `delivery_type='code'` ส่งโค้ดจาก `stock` อัตโนมัติแบบ atomic และป้องกันโค้ดซ้ำ; แบบ `manual` สร้างคำสั่งซื้อสถานะรอดำเนินการ **ยังไม่มีหน้าส่งสินค้าโดยแอดมิน**
- ไม่ใช่ระบบตรวจสลิปปลอมอัตโนมัติ ไม่ใช่ระบบเชื่อมธนาคาร ไม่ใช่ระบบคืนเงิน/เคลมอัตโนมัติ; ต้องทำเพิ่มเติมก่อนใช้งานเชิงพาณิชย์

## ติดตั้งบน Vercel ผ่าน GitHub
1. อัปโหลดไฟล์ทั้งหมด **ภายในโฟลเดอร์นี้** ไป repository (ต้องมี `app/`, `lib/`, `supabase/`, `package.json` อยู่ชั้นบนสุด)
2. สร้าง Supabase project: https://supabase.com/dashboard
3. เปิด SQL Editor วางเนื้อหา `supabase/schema_secure.sql` แล้ว Run (ทำเพียงครั้งเดียวบนโปรเจกต์ใหม่)
4. ใน Supabase Authentication ตั้งค่า Email sign-in และ Site URL ให้ตรงเว็บ Vercel
5. ใน Vercel > Project > Settings > Environment Variables เพิ่มค่าจาก `.env.example` (อย่าอัปโหลด `.env` ที่มี secret ขึ้น GitHub)
6. `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` จาก Supabase API settings (URL ต้องเป็น https://PROJECT.supabase.co โดยไม่มี /rest/v1/; ใช้ Publishable key หรือ legacy anon key เท่านั้น); `SUPABASE_SERVICE_ROLE_KEY` เป็น **secret server-only** ห้ามตั้งชื่อขึ้นต้น NEXT_PUBLIC
7. ตั้ง `BANK_NAME`, `BANK_ACCOUNT_NAME`, `BANK_ACCOUNT_NUMBER` เป็นข้อมูลบัญชีรับโอนที่ถูกต้อง
8. Deploy ใหม่ แล้วสมัครสมาชิกเพื่อทดสอบ
9. กำหนดแอดมินด้วย SQL Editor **เฉพาะ user id ที่ตรวจสอบแล้ว**: `update public.profiles set is_admin=true where id='UUID-ของเจ้าของร้าน';` อย่าให้ผู้ใช้ตั้งสิทธิ์แอดมินเอง
10. เพิ่มสต็อกเฉพาะคีย์/สิทธิ์ที่ได้รับอนุญาตใน Supabase Table Editor ตาราง `stock`; เปิด `products.active=true` เฉพาะสินค้าที่ถูกต้องและพร้อมขาย; ถ้าเป็น code ให้เปลี่ยน `delivery_type='code'`

## ทดสอบก่อนเปิดขาย
- ผู้ใช้ทั่วไปอ่าน/เปลี่ยนยอดคนอื่นไม่ได้; ห้ามเข้าหน้าแอดมินโดยไม่มีสิทธิ์
- สลิปเดิมซ้ำ, เลขอ้างอิงเดิมซ้ำ, กดอนุมัติซ้ำ ต้องไม่เพิ่มยอดอีก
- กดซื้อพร้อมกันหลายหน้าต้องไม่ติดลบ/ไม่ส่งคีย์ซ้ำ
- ไม่มีคีย์ในสต็อกต้องไม่หักเงิน; สินค้าปิดขายต้องกดซื้อไม่ได้
- ใช้ธุรกรรมทดสอบจริงกับบัญชีธนาคารและตรวจยอดด้วยมือก่อนเปิดใช้

## ข้อจำกัดและความปลอดภัย
- ระบบตรวจแค่ **hash ของไฟล์ภาพ** และเลขอ้างอิงที่แอดมินกรอก ไม่สามารถยืนยันว่ารูปสลิปแท้โดยอัตโนมัติ ต้องใช้ผู้ให้บริการตรวจสอบธุรกรรม/ธนาคารที่เชื่อถือได้เพื่อทำ auto-verify จริง
- ไม่เก็บรหัสผ่านลูกค้าหรือบัญชีของผู้ให้บริการภายนอกเป็นสต็อก; ให้ใช้เฉพาะโค้ดหรือสิทธิ์ที่ได้รับอนุญาต
- การจำหน่าย Netflix, ChatGPT, Gemini ต้องเป็นไปตามสิทธิ์การขายและเงื่อนไขของผู้ให้บริการ; อย่าเปิดขายบัญชีแชร์หรือบัญชีที่ไม่ได้รับอนุญาต
- ก่อนเปิดรับเงินจริงควรเพิ่ม rate limiting, CAPTCHA, audit logs, ช่องทางติดต่อ, นโยบายคืนเงิน/ความเป็นส่วนตัว, สำรองฐานข้อมูล, กระบวนการกระทบยอดธนาคาร และทดสอบการใช้งานจริง

## รันในเครื่อง
`npm install` แล้ว `npm run dev` (สร้าง `.env.local` จาก `.env.example`)

## หลังบ้านจัดการร้าน
เข้าสู่ระบบด้วยบัญชีที่มี `profiles.is_admin=true` แล้วเลือกแท็บ **หลังบ้าน**
- **สินค้าและราคา**: เพิ่มสินค้า แก้ชื่อ รายละเอียด ราคา เปิด/ปิดขาย และวิธีส่งสินค้า อัปโหลดรูป JPG/PNG/WEBP ไม่เกิน 5 MB หรือใส่ลิงก์ HTTPS
- **สต็อกสินค้า**: เลือกสินค้า เติมโค้ดหนึ่งรายการต่อบรรทัด (สูงสุด 200 รายการต่อครั้ง) ดูจำนวนคงเหลือ/ขายแล้ว และแก้หรือลบเฉพาะรายการที่ยังไม่ขาย โค้ดซ้ำในสินค้าเดียวกันจะถูกปฏิเสธ
- **ข้อความหน้าร้าน**: แก้ชื่อร้าน หัวข้อ คำอธิบาย ประกาศ ช่องทางติดต่อ และข้อความท้ายเว็บ บันทึกแล้วหน้าร้านจะแสดงค่าใหม่

ฐานข้อมูลใช้ migration ใน `supabase/migrations/` สำหรับโปรเจกต์เดิม (ห้ามรัน initial schema ซ้ำ) รูปสินค้าอยู่ใน public bucket `product-images` ส่วนสลิปยังอยู่ใน private bucket เดิม ทุกการเขียนข้อมูลตรวจสิทธิ์แอดมินผ่าน RLS โดยไม่เปิดเผย service-role key ให้เบราว์เซอร์

ทดสอบหน้าแอดมิน: รัน `npm run dev -- --port 3001` แล้วเปิดอีก terminal รัน `npm run test:admin` (ต้องมี Chromium ที่ `/usr/bin/chromium` หรือกำหนด `CHROMIUM_EXECUTABLE_PATH`) การทดสอบนี้ใช้ข้อมูลจำลอง ไม่แก้ข้อมูลจริง

- **บัญชีธนาคาร** ในหลังบ้าน: กรอกชื่อธนาคาร ชื่อบัญชี และเลขบัญชีแล้วบันทึก ข้อมูลจะแสดงในหน้าเติมเงิน เลขบัญชีเก็บเป็นข้อความเพื่อรักษาเลขศูนย์นำหน้า ล้างทั้ง 3 ช่องเพื่อปิดแสดงบัญชี ข้อมูลส่วนนี้จัดการจากฐานข้อมูลแทน BANK_* environment variables

## สต็อกหลายอีเมลและจำนวนสิทธิ์
ใน หลังบ้าน → สต็อกสินค้า เลือกสินค้า แล้วกรอกช่อง **เติมหลายอีเมล** รูปแบบ `อีเมล | จำนวน | ข้อมูลส่งมอบ` หนึ่งอีเมลต่อบรรทัด สูงสุด 200 อีเมลต่อครั้ง ใช้ \n ในข้อมูลส่งมอบเพื่อขึ้นบรรทัดใหม่
ตัวอย่าง: `member@example.com | 4 | ข้อมูลการใช้งาน` จะขายอีเมลพร้อมข้อมูลนี้ได้ 4 ครั้ง ครั้งละ 1 สิทธิ์ แก้จำนวนคงเหลือได้ หรือกำหนด 0 เพื่อหยุดขาย ระบบป้องกันอีเมลซ้ำในสินค้าเดียวกัน
การขายอัตโนมัติต้องตั้งวิธีส่งสินค้าเป็น **ส่งโค้ด/อีเมลจากสต็อกอัตโนมัติ** ระบบเลือกอีเมลที่ยังมีสิทธิ์ก่อน แล้วใช้โค้ดเดิมเมื่อสต็อกอีเมลหมด หักจำนวนและยอดเงินในธุรกรรมเดียว เก็บข้อมูลส่งมอบเป็น snapshot ในแต่ละคำสั่งซื้อ อีเมลที่ขายแล้วลบไม่ได้ แต่แก้ข้อมูลสำหรับคำสั่งซื้อถัดไปได้ ประวัติเดิมยังคงอยู่
`npm run test:stock` ทดสอบการอ่านหลายอีเมลและการตรวจสอบข้อมูล; `npm run test:admin` ทดสอบการจัดการผ่านเบราว์เซอร์ด้วยข้อมูลจำลอง

## หมวดหมู่สินค้า
มีหมวด Netflix, ChatGPT และ Gemini พร้อมจัดสินค้าที่มีชื่อแอปเหล่านี้เข้าหมวดให้แล้ว หลังบ้าน → หมวดหมู่สินค้า ใช้เพิ่มหมวดใหม่ เปลี่ยนชื่อ และจัดลำดับ จากนั้นเลือกหมวดในฟอร์มสินค้า หน้าร้านกรองสินค้าตามหมวดได้ ทั้งผู้เยี่ยมชมและสมาชิก

## ตรวจสลิปอัตโนมัติ (EasySlip API v2)
สมัครผู้ให้บริการและเลือกค่าแพ็กเกจด้วยตนเอง ลงทะเบียนบัญชีรับเงินใน EasySlip ให้ตรงกับหลังบ้านร้านทั้งธนาคาร เลขบัญชี และชื่อบัญชี เพิ่ม `EASYSLIP_API_KEY` เป็น **Secret ฝั่งเซิร์ฟเวอร์** ใน Vercel แล้ว deploy ใหม่ ห้ามใช้ NEXT_PUBLIC กับคีย์นี้ เมื่อมีคีย์ระบบเปลี่ยนเป็นอัตโนมัติ ตั้ง `SLIP_AUTO_VERIFY_ENABLED=false` เพื่อคงการตรวจด้วยผู้ดูแล
ระบบส่งไฟล์ให้ https://api.easyslip.com/v2/verify/bank พร้อม matchAccount, matchAmount และ checkDuplicate ต้องได้ผลชัดเจนว่าผู้รับ ยอด ธนาคาร ชื่อบัญชีตรง และไม่ซ้ำก่อนเพิ่มยอด รับสลิปไม่เกิน 4 MB โอนภายใน 24 ชั่วโมงและไม่ก่อนสร้างบัญชีเกิน 5 นาที ตรวจทั้ง hash รูปและเลขอ้างอิงธุรกรรมที่ unique ในฐานข้อมูล เก็บสลิปใน private storage จำกัด 5 รายการต่อผู้ใช้ต่อนาที และเพิ่มยอดพร้อม ledger ใน transaction เดียว
บริการตรวจไม่ได้/โควต้าหมด/ผลไม่ครบให้คง pending โดยไม่เพิ่มเงิน รายการที่ตรวจไม่ผ่านให้ rejected ถ้ามีการตรวจแล้วแต่ระบบเพิ่มยอดล้มเหลว ให้ผู้ดูแลตรวจธุรกรรมจริงก่อนจัดการต่อ ไม่อนุมัติซ้ำจากภาพเพียงอย่างเดียว การตรวจยืนยันข้อมูลธุรกรรม ไม่ใช่การรับประกันความแท้ของทุกพิกเซลหรือพิสูจน์ว่าผู้อัปโหลดเป็นผู้โอน
เอกสารผู้ให้บริการ: https://document.easyslip.com/en/v2/verify/bank/

## SlipVerify ทางเลือก (xNearbyTeam)
รีโป https://github.com/xNearbyTeam/Slip-Verify เป็น SDK/ตัวอย่างที่เรียก API ภายนอก ไม่ได้เปิดเผย server ตรวจธุรกรรม ขอ Token ผ่าน Discord ตาม README แล้วเพิ่ม `SLIPVERIFY_API_TOKEN` เป็น Vercel Secret ฝั่ง Production และ deploy ใหม่ หากมีทั้งสองคีย์ SlipVerify จะถูกเลือกก่อน EasySlip
ตัวเชื่อมส่งชื่อบัญชี รหัสธนาคาร และเลขบัญชีเต็มให้ `/slipVerify/v2` และตรวจยอด เลขอ้างอิง วันเวลาที่มี timezone และข้อมูลผู้รับซ้ำฝั่งร้าน ไม่เพิ่มยอดอัตโนมัติจากเพียงยอด OCR หรือเลขบัญชีท้ายบางหลัก หากผลตอบกลับมีบัญชีถูกปิดบัง ชื่อย่อที่ไม่ตรง หรือข้อมูลไม่ครบ จะคง pending เพื่อไม่เพิ่มเงินผิดคน การเชื่อมต่อจริงและรูปแบบ response ต้องทดสอบด้วย Token ของผู้ให้บริการก่อนเปิดใช้เงินจริง README ของผู้ให้บริการระบุว่าแจก Token ฟรี แต่ต้องยืนยันเงื่อนไขกับเจ้าของบริการเอง
